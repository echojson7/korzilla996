# EOKIT · архитектура

Для тех, кто меняет кит. Как им пользоваться — `README.md`.

Кит самостоятельный: токены, стили, модули поведения, ядро, сторонние библиотеки
и шрифт лежат в `eokit/`, из других папок репозитория ничего не грузится. В
разработке сборки нет: файлы отдаются как есть, ES-модулями. Для выкладки
`tools/build.mjs` собирает стили в один файл и вписывает предзагрузку модулей.

## Слои

```
приложение (admin2, витрина; admin заморожена)
   │  классы .ui-*, data-*, события <модуль>:<действие>, kit.js
   ▼
kit.js ─────────── каталог модулей, load / mount / unmount / kit(name), setTheme
   │
components/<имя>/ ─ компонент целиком: стиль и поведение, один модуль = один компонент
   │  импортирует только core/, vendor/ и свою папку (и, явно, модуль-оверлей:
   │  таблицы → popover, фильтр → select, редактируемый список → sortable; список — ALLOWED в tools/lint.mjs)
   ▼
core/ ──────────── примитивы без состояния страницы: DOM, жизненный цикл, слои,
   │               позиционирование, вход и уход, фокус, жесты, наблюдатели, иконки
   ▼
styles/ ────────── tokens.css → base.css → surface.css, card.css (общее для компонентов)
```

Зависимости идут только вниз. Ядро не знает о компонентах, компонент не знает о
приложении. Связи между компонентами — через публичный API модуля (`popover.open`),
а не через чужие классы и подставные клики.

## Модуль компонента

Модуль описывается через `defineComponent` и экспортирует его результат:

```js
import { defineComponent } from "../../core/component.js";

export default defineComponent({
  name: "popover",
  selector: "[data-ui-popover]",        // нет selector — программный модуль
  create(host, ctx, options) {          // → экземпляр или null (разметка не та)
    ctx.on(trigger, "click", onClick);  // снимется само при unmount
    return { open, close, destroy() { … } };
  },
  api: ({ get }) => ({                  // методы модуля сверх mount/unmount/get
    open: (host, o) => get(host)?.open(o),
  }),
});
```

`setup()` модуля возвращает замороженный объект: `mount(root)`, `unmount(root)`,
`get(host)`, `create(host, options)` и методы `api`. Повторный `mount` того же хоста
ничего не делает. `unmount(root)` снимает экземпляры на `root` и внутри него.
`ctx`: `signal` (AbortSignal экземпляра), `on(target, type, fn, opts)`,
`emit(type, detail, opts)` (с хоста, всплывает; имя `type` уходит как есть), `cleanup(fn)`.

Программные модули (`tableView`, `filterBuilder`) по разметке не ставятся:
`kit("tableView").create(host, options)`. `unmount(root)` снимает и их.

Правила модуля:
- На импорте нет работы: ни DOM, ни `await`, ни таймеров. Всё — в `create`.
- Разметка, которую модуль добавил, снимается в `destroy`; атрибуты автора
  возвращаются через `snapshot`/`restore`.
- Строки интерфейса — из `core/locale.js`, не литералы: `const t = messages("datepicker",
  { ru, en })`, затем `t("pick")`. Приложение переопределяет их
  `setMessages("en", { "datepicker.pick": … })`.
- Иконки — `icon(name)` из `core/icons.js`, готовым `<svg>`.
- Событие — `ctx.emit("tabs:change", detail)`: модуль передаёт полное имя
  `<имя-через-дефис>:<действие>`, префикс сам не добавляется. Голое `change` смешалось
  бы с нативным `change` полей.

## Оверлеи

Поповер, меню, выпадашка, селект, календарь, выбор цвета, подсказка, окно, лист, палитра, тур, просмотр карусели
и меню перетаскивания строятся из одних примитивов:

- `core/layer.js` — один стек открытых слоёв. Слушатели (`pointerdown` и `focusin` на
  window, `keydown` на document — в фазе захвата) висят, только пока стек не пуст;
  жест (`track`) ловит Esc на window раньше и отменяет перетаскивание, не закрывая
  слой вокруг. Esc закрывает
  верхний слой с `escape` и гасит событие. Нажатие снаружи закрывает слои сверху
  вниз до первого, внутри которого нажали; «внутри» — это элементы слоя и его
  открытых детей. Слой-ребёнок открывается над родителем; `exclusive` закрывает
  соседнюю ветку. Портал уносит панель в ближайший `[data-ui-layer]` или в body и
  возвращает на место по метке-комментарию.
- `core/floating.js` — `computePosition` (чистая функция: сторона с переворотом,
  выравнивание с RTL, прижим к кромке, место до кромки, стрелка, origin) и `place`,
  который за одно чтение и одну запись ставит `data-side`, `data-align` и
  `--ui-<имя>-x/-y/-space`. `autoUpdate` держит открытые панели у якоря: общие
  слушатели прокрутки и размера и один ResizeObserver на всех, раз в кадр.
- `core/presence.js` — вход и уход по `data-state`: `open` → `closing` → `hidden`.
  Конец ухода — конец CSS-анимаций элемента (`getAnimations`), а не таймер; повторное
  открытие во время ухода его отменяет. Длительности живут только в CSS.
- `core/focus.js` — фокус при открытии (с клавиатуры — внутрь, мышью — на
  поверхность), Tab по кругу в модальных слоях, возврат фокуса.

Почему портал, а не top layer (`popover="manual"`): панель в top layer наследует
стили места, где стоит хост (шапка таблицы, кнопка), и всегда выше всего, что не в
top layer, — тосты и окна кита оказались бы под меню. Перенос узла в body стоит один
пересчёт стиля небольшой панели при открытии; повторное открытие во время ухода
панель не двигает.

Меню (`.ui-popover__menu`) ведёт поповер: стрелки, Home/End, → и ← для подменю,
Tab закрывает меню. Пункт с `data-pick` шлёт `menu:pick` на триггер своего меню и
закрывает всю цепочку (кроме `data-keep`) — приложению не нужны свои обработчики
выбора и подставные клики.

Сетка размеров — HeroUI v3, ужатая на ступень (4 px), все высоты кратны 4. Контролы
со строкой текста (кнопка, поле, селект, число, бейдж и чип, вкладки, сегменты,
пагинация) берут один шаг шкалы из `tokens.css`: высота xs/sm/md/lg = 24/28/32/36,
отступ h/2 − 4 (`--ui-control-px*`), скругление h/4 + 2 (`--ui-control-r*`:
8/9/10/11), текст 13 у xs и sm и 14 у md и lg, иконка 14 у xs и 16 дальше, зазор
4 у xs и 6 дальше (`--ui-control-icon*`, `--ui-control-gap*`). Новый контрол
берёт эти токены, а не свои числа. Та же формула скругления — у клавиши (20 → 7,
16 → 6), аватара и плитки иконки; вложенный контрол скруглён параллельно краю:
радиус внешнего минус отступ до него. Поверхности скругляются по роли, а не по
размеру: без отступа (таблица, список) — `--ui-r-surface` 8, с отступом
(карточка, плашка) — `--ui-r-card` 12, окно — `--ui-r-modal` 16; таблица в
карточке берёт углы карточки. Строки меню, таблицы и props — 32 (малые 28;
меню и списки селекта — 32 при любом размере поля, малые только по
`data-menu-size="sm"` или малому поповеру);
аватары 20/24/32/40, kbd 20 (малый 16), счётчик 18 (цифры 12), флажок 16 (малый 14,
крупный 20), свитч 36×20 (малый 30×16, ручка — высота − 4); строка списка 48
(малая 40). Всё, что лежит внутри контрола (иконка, действие, kbd), считается от
его высоты: действие h − 8 в 4 px от края, иконка — на отступе поля.

## Правила вида

Правило записывается один раз в ките — токеном или общим правилом CSS — и
держит все места сразу. Заплатка в приложении («здесь 9px», «тут свой
[hidden]») чинит один экран и ломается на соседнем; если её хочется написать,
значит, в ките не хватает правила.

- **Отступы — по шкале** (`tokens.css`, «Отступы»): до 16 шаг 2, дальше шаг 4,
  1 px — только компенсация линии. Число, выведенное из размеров, пишется
  формулой из чисел шкалы: `calc(10px + 14px + 6px)` — место значка из отступа,
  значка и зазора. Проверяет `tools/lint.mjs` в ките, admin2 и витрине.
- **Отношения — токены, а не числа:** подпись → поле `--ui-field-gap`, поле →
  поле `--ui-form-gap`, легенда → пункты `--ui-choice-legend-gap`, пункт → пункт
  `--ui-choice-gap` (с описанием `--ui-choice-gap-desc`). Таблица — в
  `tokens.css`. Заголовок группы стоит дальше от пунктов, чем пункты друг от
  друга, иначе он не читается заголовком.
- **Край с иконкой** у контрола — ⅔ обычного отступа (`--ui-control-icon-pad`):
  у иконки свой пустой край в рамке 24. Строка списка (пункт меню) ставит долю
  1, чтобы иконки шли столбцом с текстом соседей.
- **`[hidden]` прячет всегда** (base.css, `!important`). Компоненту не нужен
  свой `[hidden] { display: none }`; кто держит место скрытого, пишет display
  с `!important` рядом и объясняет почему.
- **Шеврон раскрытия** — `data-ui-turn` на иконке (`flip` — раскрыто вверх,
  `fold` — свёрнуто вправо), угол из `aria-expanded` кнопки вокруг. Свой
  `rotate` по `[data-closed]` в приложении не пишется.
- **Цифры пропорциональные везде** — `tabular-nums` и `tnum` не используются
  (решение владельца, проверяет lint).

Каждое сочетание компонента видно на витрине в группе «Состояния»
(`showcase/sections/states.js`): варианты × содержимое кнопки, группы выбора с
легендой и описаниями, поля с пояснением и ошибкой. Новый вариант или размер
добавляется туда же — тогда `check.mjs --shots … --compare …` покажет, что
правка задела соседние случаи, до пуша, а не на экране у владельца.

Движение: вход поверхностей ~200 мс по `--ui-ease` (кривая листа iOS), уход ~100 мс,
строки, по которым ведут мышью, подсвечиваются мгновенно.

## Производительность

JS:
- Никакой работы на импорте и в `setup()`; модуль грузится, когда его просят.
- Окно-слушатели и наблюдатели — только пока нужны (открыт слой, идёт жест).
- Один общий ResizeObserver (`core/observe.js`): чтения всех целей, потом записи.
  Первое измерение — из первого колбэка наблюдателя, не синхронно в `create`.
  Исключение — Embla в карусели: её размер ведёт общий наблюдатель (`watchResize:
  false` + `reInit()`), но свой слушатель `visibilitychange` и IntersectionObserver
  она держит сама, опцией они не отключаются.
- Геометрия: сначала все чтения, потом все записи. `setVar`/`setAttr` пишут только
  изменившееся. Токены читаются одним `getComputedStyle` на действие.
- Тяжёлое — кусками с `yieldToMain`, сортировка больших таблиц — в воркере.
- `kit.load` не тянет лишнего: всегда грузится только `icons` (иконки из разметки),
  остальное — по имени.

CSS:
- Вариант меняет переменные, правило отрисовки у компонента одно. Размеры
  самого компонента (высота свитча, отступ бейджа) — его переменные в начале
  правила; общие шкалы и все цвета — в `tokens.css`.
- Правая часть селектора — класс или атрибут компонента. Никаких глобальных
  `:root:has(…)` / `body:has(…)`, `*` вне base.css, подстрок `[class*=…]`.
- Движение — `transform` и `opacity` (заливка прогресса тоже едет трансформом), цвет
  меняют переходы отдельных контролов; строки, по которым ведут мышью, без переходов.
  Раскладку анимируют только раскрытия и мелкие метки, где трансформ не годится:
  высота аккордеона, `grid-template-rows` дерева разделов и ветки перетаскивания,
  ширина активной точки карусели (и текущей точки ряда шагов), край ручки ширины
  столбца и размер выреза тура: он один, в корне со строгим `contain`, и
  перекладка не выходит за него.
- Место панели (`--ui-<имя>-x/-y/-space`) зарегистрировано через `@property` без
  наследования: запись на панель не пересчитывает стиль её содержимого.
- Бесконечные анимации (спиннер, скелетон) не тикают вне экрана.
- Живое движение — пружины `--ui-spring` (перелёт ~1 %: панели, окна, вкладки,
  тосты), `--ui-spring-bounce` (~4 %: появление сообщения, отметка, бейдж),
  `--ui-spring-smooth` (без перелёта: листы, страницы, сдвиги) и
  `--ui-spring-press` (отпускание нажатого). Кривые — `linear()` затухающей
  пружины из `tools/springs.mjs`, длительность — токен `-time`. Пружина только
  на входе и на отпускании: уход — короткий ease-in. Нажатие вдавливается за
  `--ui-press-in` с ease-out, а `:active` переопределяет только длительность
  и кривую `transform`, переход в покое — пружина.
- Уровень движения — `data-ui-motion` на `<html>` (`setMotion`): `lite` для
  слабых машин (по умолчанию «auto» — до четырёх ядер или гигабайт памяти)
  подменяет пружины короткими ease-out, гасит каскады и анимацию раскладки;
  `off` — как reduced motion, его же видит `reducedMotion()`. Новое движение
  берёт токены — тогда lite достаётся бесплатно; правило, которому токенов
  мало, само смотрит на атрибут.
- Вход вставленного элемента без JS — `.ui-enter` / `.ui-enter--pop`
  (`@starting-style`), из JS — `pop(el)`; уход строки с доездом соседей —
  `leave(el)`, толчок изменившегося значения — `bump(el)`.
- Порталы и прокручиваемые области изолированы `contain`.
- Смена темы — `setTheme`: переходы цвета, которые она запустила, сразу доводятся
  до конца (`getAnimations`), иначе каждый цвет анимируется отдельно. Класс,
  выключающий переходы, стоил бы второго пересчёта всей страницы.

## Стили

- Все значения — в `styles/tokens.css`, и светлая тема, и тёмная: тему меняют в
  одном файле. Стиль компонента берёт `var(--ui-*)`; литерал цвета вне токенов
  не пропустит `tools/lint.mjs` (исключение — `#000` в масках, это альфа).
- Длины и длительности, которые читает JS, записаны в px и мс:
  `--ui-popover-gap/-edge`, `--ui-select-gap`, `--ui-datepicker-gap/-edge`, `--ui-colorpicker-gap/-edge`,
  `--ui-tooltip-gap/-edge/-arrow-inset`, `--ui-modal-exit/-morph/-fade`,
  `--ui-alert-move/-exit`, `--ui-sortable-dur`, `--ui-repeater-in/-out`, `--ui-duration-fast`,
  `--ui-tour-gap/-edge/-pad/-r`.
- Порядок в `kit.css` — порядок каскада. Компонент, который перенастраивает чужие
  части (пункты меню — это `.ui-btn`, поле в чипе фильтра — `.ui-input`), стоит
  после них. Новый файл стилей без строки в `kit.css` не пропустит lint.
- Без `@layer`. Слои отдали бы приложению победу над китом без войны
  специфичности, но любое правило приложения без слоя — даже сброс вроде
  `p { margin: 0 }` — тогда сильнее любого правила кита. Проба (17.10.2026)
  изменила вид аккордеона на витрине и семи экранов admin2, а замороженную admin
  поправить нельзя. Вернуться к слоям можно, когда приложения сами положат свои
  сбросы в слой.

## Как добавить компонент

1. Папка `components/<имя>/`, в ней `<имя>.css`; строка `@import` в `kit.css` на
   место по каскаду.
2. Есть поведение — `<имя>.js` через `defineComponent` (ниже) и строка в каталоге
   `kit.js`. Строки интерфейса — `messages()` из `core/locale.js`, иконки —
   `icon()` из `core/icons.js`, значения — новые токены в `tokens.css`.
3. Блок на витрине (`../showcase/sections/`), его сочетания — в «Состояниях»
   (`states.js`), и сценарий в `tools/check.mjs`, если у компонента есть поведение.
4. Строка в таблице компонентов `README.md`, запись в `CHANGELOG.md`.
5. `node eokit/tools/lint.mjs`, `node --test eokit/tests/unit/*.test.mjs`,
   `node eokit/tools/check.mjs`.

## Шрифт

Inter 400/500/600, hinted. Основной файл веса — латиница, кириллица, знаки, валюты,
стрелки и математика (~52 КБ); дополнительный — остальные символы Inter, грузится,
только если такой символ встретился на странице (`unicode-range`). Предзагружаются
основные 400 и 500.

## Проверка

```
node eokit/tools/lint.mjs                         # правила кита
node --test eokit/tests/unit/*.test.mjs           # ядро и «на импорте нет DOM»
node eokit/tools/check.mjs                        # сценарии витрины, консоль чистая
node eokit/tools/check.mjs --only кнопка          # только сценарии со словом в названии
node eokit/tools/check.mjs --shots d --compare p  # снимки и сравнение с прошлыми
node eokit/tools/perf.mjs                         # загрузка и отклик, CPU ×4
node admin2/tools/check.mjs                       # приложение на ките
node eokit/tools/build.mjs                        # сборка для выкладки → eokit/dist/
```

Перед выкладкой — та же `check.mjs`, запущенная на сборке: витрина рядом с
`dist/`, положенной на место `eokit/`, должна дать те же снимки.
